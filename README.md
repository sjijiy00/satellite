목적·사용자 확정 AOI·UTC 기간을 한 번 입력하면 기존 규칙으로 관측 방식·제품을 추천하고, 명시 검색에서 **Earth Search S2 L2A/Landsat C2 L2 + Planetary Computer S2 L2A/Landsat8·9 C2 L2 + NOAA-20 VIIRS NDVI CDR + Copernicus Sentinel-1 GRD + NASA CMR Suomi NPP VIIRS VNP09GA.002**를 제품 조건에 맞춰 조회합니다. 한 제공처 실패는 다른 결과와 별도로 표시합니다. 결과에는 검색 제공처·제품·원래 해상도/출력 격자·원본 Item·파일 접근·픽셀 QA·처리 지원을 구별합니다.

VIIRS는 광역 식생의 조건부 참고 후보로 500 m/1 km 일별 제품입니다. 상세 10 m 영상의 동등 대안이 아닙니다. Sentinel-1 GRD와 VIIRS에 기존 S2 A3/A4·관측 합성·국소 ML을 적용하지 않습니다. 메타데이터는 무키 검색이지만 원본 권한은 별도입니다. NASA 공개 browse는 서버에서 전체 이미지 수신·디코딩 후 표시하며, 사용자별 Earthdata 연결과 제한된 VIIRS 원본 전송·OAuth 갱신 코드도 있습니다. **실제 앱 등록·사용자 로그인·인증 원본 다운로드·실제 토큰 갱신은 미검증**입니다. 개인 토큰을 공용 `.env`에 넣지 않습니다. [제공처별 실제 접근 결과·상한·미검증](docs/PROVIDER_MEDIA_ACCESS.md)을 확인하세요.

NOAA NODD GOES, GK2A, NOAA-21 VIIRS·SLSTR는 등록 후보/설계이며 앱 내 미연결입니다. NOAA-20은 이번 NDVI CDR만 연결했고 VJ109GA 등 다른 제품은 미연결입니다. 전 세계 모든 제품을 지원한다고 주장하지 않습니다. [제공처·제품 등록/발견 API, 인증 조사표, 상한, 실제 응답과 후속 연결 순서](docs/MULTI_PROVIDER_SEARCH.md)를 확인하세요. 비밀키를 새로 설정할 필요 없이 현재 검색을 사용할 수 있으며 OpenAI 자연어 설정은 위성 검색 키와 무관합니다.

검색 버튼 위의 **최종 검색 컬렉션**을 확인하세요. 추천 카드를 고르면 해당 제품의 컬렉션이 선택되고, 이후 위성 선택 방식이나 수동 체크박스를 바꾸면 카드 선택을 해제합니다. 결과에는 서버가 실제 적용한 컬렉션·추천 조건·AOI도 표시합니다. VNP09GA는 일별 지표반사도이며 산불/야간조명 제품이 아닙니다.

백엔드 실행에는 자동 reload가 없습니다. Python 코드 변경 후에는 진행 중 분석/다운로드 여부를 확인하고 **해당 프로젝트 서버만** 종료한 뒤 루트 `.\start.cmd`로 다시 시작하세요. 웹/health 200만으로 최신 코드가 반영됐다고 판단하지 말고 `/catalog`와 웹 `/api/catalog`에서 현재 등록된 5개 제공처·7개 컬렉션을 확인하세요. 2026-10-30 사용자 작업 부재 확인 후 현재 3000/8000 서버에 반영·실검색 검증을 마쳤으며 상세 성공/간헐 실패는 최신 TEST_REPORT에 기록했습니다.

## 1. 준비물

자연어 AI 조건 연결은 목적·기간·장소를 별도 단계로 표시합니다. AI로 추출한 목적/명시 UTC 기간은 수동 수정값과 충돌하지 않으면 같은 검색 폼에 반영합니다. 미등록 지명도 원문을 보존하며 `지명 인식됨`과 `위치 검색 미설정/실패`를 구분합니다. 사용자가 선택한 **Kakao 서버 키 방식**으로 국내 행정 지명을 확인합니다. 설정 후 확인한 중심점은 지도 이동에만 사용하고 AOI는 사용자가 직접 지정·확정합니다. 서버 전용 변수는 `GEOCODER_ENABLED`, `KAKAO_LOCAL_REST_API_KEY`이며 기존 OpenAI 키·위성 제공처 인증과 별개입니다. `.env` 변경 후 실행 서버에 반영해야 하며 키 존재·설정 인식·실제 조회 성공을 구별합니다. [설정·제공 범위·상태·실검증 한계](docs/AI_PLACE_CONDITIONS.md)를 확인하세요.

이전 규칙 계약(현재 기본/실패 경로에서 미사용)은 `2025년 8/15~8/30까지`처럼 시작에 명시된 연도를 종료일에 공유하는 월·일 범위를 인식합니다. 종료 월·일이 빠지거나 범위가 역전되면 기간을 임의로 확정하지 않습니다. 문장의 지명은 지도 이동 제안이며 AOI 자동 지정은 하지 않습니다.

- Windows PowerShell, Node.js 22 이상, Python 3.11 이상(이 환경에서는 Node 24.22.1 / Python 3.13.14 검증)
- 인터넷 연결. 검색은 Earth Search·Copernicus Data Space·NASA CMR, 지도 배경은 OpenStreetMap, 미리보기는 제공처 서버를 사용합니다.
- 현재 자연어 자동 해석은 기존 서버 OpenAI 키·모델로 문장을 전송하며 사용량·비용이 발생할 수 있습니다. 직접 조건 입력·과학적 추천·위성 검색은 별도 AI 호출 없이 사용합니다. 과거 명시 AI 버튼 계약은 상단의 현재 계약 링크로 대체되었습니다. [설정과 호출/비용 제한](docs/AI_NATURAL_INPUT.md)을 확인하세요.
- WebGL을 지원하는 최신 Edge/Chrome. 지도가 초기화되지 않으면 좌표 입력 검색은 가능합니다.

### Earthdata 계정 연결 (NASA 원본 접근 준비)

화면 상단의 `Earthdata 계정 연결`은 **각 사용자가 NASA 로그인 화면에서 직접 승인하는 기능**입니다. 사이트 운영자가 Earthdata에 이 애플리케이션을 등록해 client ID/secret과 정확한 callback URL을 받은 뒤 서버 전용 `backend/.env`에 아래 세 항목을 직접 설정해야 버튼이 활성화됩니다. 개인 계정 화면에서 만든 User Token을 붙여넣는 칸이 아닙니다.

```dotenv
EARTHDATA_CLIENT_ID=
EARTHDATA_CLIENT_SECRET=
EARTHDATA_REDIRECT_URI=http://127.0.0.1:3000/api/auth/earthdata/callback
```

위 주소는 **NASA가 로컬 HTTP callback 등록을 허용한 경우에만** 쓰는 예시이며 등록한 값과 정확히 일치해야 합니다. 앱 등록 자격·승인과 대상 파일 권한은 NASA에서 확인해야 합니다. 미설정 시 `연결 준비 중`입니다. 연결 성공은 **계정 인증**만 뜻합니다. VIIRS 원본은 선택한 파일별 GET 범위 접근을 확인한 뒤 별도 `원본 다운로드`로 전체 수신하며 파일당 256 MiB 상한입니다. 실제 발급된 OAuth refresh token이 있을 때만 만료 임박/401에 제한적으로 갱신합니다. 개인 User Token 갱신 API와는 다릅니다. 실제 사용자 인증 검증은 아직 실행하지 않았습니다.

기본 세션은 로컬 단일 프로세스 메모리에서 최대8시간이며 재시작 시 해제됩니다. Windows에서 `EARTHDATA_PERSIST_SESSIONS=1`을 명시하면 사용자 범위 DPAPI 암호화 저장과 최대30일 연결 복원을 지원합니다. access token 수명·갱신·철회는 실제 제공처 응답을 따릅니다. **공유 암호화 세션 저장소를 구현하기 전에는 공개 callback을 허용하지 않습니다.** [로그인 유지 설정과 폐기 실패 제한](docs/AUTOMATIC_PREVIEWS.md), [실제 구현·보안 상한](docs/PROVIDER_MEDIA_ACCESS.md)을 보세요. 비밀값을 채팅이나 프런트 설정에 넣지 마세요.

## 4. 사용 순서

1. 예: `영천군의 2025년 8월 식생상태를 확인하고 싶어`를 목적에 입력하면 일시 정지/blur 후 기간을 2025-08-01~31로 반영하고 지도 카메라만 해당 지역으로 이동합니다. 영천군은 현재 영천시 참고 위치로 안내하는 옛 지명입니다. 지명으로 AOI 사각형이나 좌표를 만들지 않습니다. 기존 수동 날짜는 보호하며 충돌 시 `문장에서 다시 적용`은 날짜만 갱신합니다. 기본 자동 해석은 규칙 기반이며 선택형 `AI로 문장 해석`은 설정 후 명시 버튼에서만 호출합니다. [해석·지명·AI 설정 안내](docs/AI_NATURAL_INPUT.md)를 보세요.
2. 날짜를 지정합니다. 시작·종료일 전체를 **UTC** 기준으로 검색합니다.
3. `영역 선택`을 누르고 지도에서 대각선 두 꼭짓점을 클릭합니다. 또는 서·남·동·북 좌표를 입력하고 `좌표 적용`을 누릅니다. 지도 두 꼭짓점을 지정한 경우 `분석 AOI 확정`을 누릅니다. AOI 확정 전에는 검색/픽셀 처리를 실행하지 않습니다. 새 지명과 기존 AOI가 다를 수 있으면 유지/새 선택을 확인하며 기존 좌표를 조용히 바꾸지 않습니다. `충남 예시 영역`은 좌표만 채우며 검색 결과를 생성하지 않습니다.
4. 목적에 필요한 관측 방식·탑재체·제품 카드를 확인합니다. 선택 입력에서 대상 크기, 한 시점/전후 변화, 구름·야간 관측 필수 여부를 지정할 수 있습니다. 미입력 가정은 카드 위에 표시됩니다. 카드의 `이 제품 선택`으로 제품을 고른 뒤, 추천 아래 하나의 `위성영상 검색` 버튼을 누릅니다. 제품 선택만으로는 검색하지 않습니다. 검색은 현재 AOI·기간을 유지하고 연결된 컬렉션·플랫폼·제품 수준·필수 밴드 메타데이터 조건을 적용합니다. 기존 컬렉션 자동/직접 선택 검색도 사용할 수 있습니다.
5. `위성영상 검색`을 누릅니다. 결과 목록, 원본 STAC 링크, 촬영 범위를 확인합니다. 지도는 확정 AOI로 확대됩니다. 영상의 `지도에서 선택` 버튼이나 지도 촬영 범위를 누르면 날짜·상세 정보·목록 선택이 함께 바뀌고 선택 범위는 주황색으로 강조됩니다.
6. 지도 아래 `날짜별 실제 영상`에서 현재 기간에 검색된 UTC 날짜를 선택합니다. 해당 날짜의 목록으로 좁혀지고 선택 장면·지도 강조가 함께 이동합니다. `전체`로 돌아올 수 있습니다. 장면 구름량 미확인, 촬영일 누락, 확정 기간 밖 Item은 별도로 안내합니다. 기간 밖/날짜 미확인 Item은 날짜 탐색·지도·비교에서 제외합니다. 기간을 바꾸려면 입력을 수정하고 다시 검색해야 합니다.
7. 장면 선택 후 결과 아래 `다음 작업`의 `두 장면 비교·분석`을 열고 `여러 영상 비교와 해석`에서 `센서 후보 비교` 또는 `전후 변화용 영상 선택`을 고릅니다. 비교 영상 1·2의 촬영 범위는 동일 AOI 지도에서 보라·분홍 선으로 구분합니다. 전후 모드는 같은 컬렉션·센서(instruments)·제품 유형이 확인된 다른 촬영 시점을 우선하고 이전→이후 순서로 기본 선택합니다. 호환 후보가 없으면 두 번째 선택은 비워 둡니다. 동일 Item, 역전 날짜, 동일 시각, 센서·제품 불일치 및 AOI 내 공통 촬영 영역 없음/미확인을 안내합니다. 공통 영역 검사는 footprint의 양의 면적 교집합 존재만 확인하며 실제 면적·픽셀 품질 검사는 아닙니다. 미리보기는 제공처 원본이며 합성·정합하지 않습니다.
8. 결과는 `목적별 우선 추천`과 `다른 위성·추가 후보`로 나뉘며 각 그룹에서 10건씩 이동합니다. 지도에는 이번 조회의 현재 기간 후보 촬영 범위를 표시합니다. 식생·도시·침수 광학 보완은 Sentinel-2, 열환경은 Landsat를 우선하는 앱의 탐색 규칙이며 모든 상황에서 우월하다는 판정이 아닙니다.
9. 카드의 `밴드 선택·다운로드`에는 목적별 분석·추천 시각화·제공된 품질 밴드가 기본 선택됩니다. `전체 선택`, `선택 해제`, `목적 추천으로 복원`, `추천 시각화 밴드`를 사용할 수 있습니다. 전체 선택에는 같은 밴드의 COG/JP2 등 다른 형식이 포함됩니다.
10. 그룹 페이지를 이동해도 밴드 선택은 유지됩니다. 새 검색이나 조건 변경은 결과와 선택을 초기화합니다. 검색 중 목적·날짜·좌표·위성·한도를 변경하면 이전 요청을 취소하고 늦게 도착한 응답도 무시합니다.
11. 각 파일 다운로드 링크를 누르거나 선택한 공개 URL 목록을 `.txt`로 저장할 수 있습니다. 목록 저장은 영상 파일 일괄 다운로드가 아닙니다. 실제 STAC Asset의 공개 HTTP(S) 주소로 연결하며 전체 장면 원본입니다. S3·요청자 비용 자료는 제한을 표시하고 직접 다운로드 버튼을 제공하지 않습니다.

### 접근 제한 파일과 외부 자료 포털

- S3 또는 요청자 비용 Asset의 제한을 앱에서 해제하지 않습니다. 제한된 파일을 선택하면 같은 **Item과 밴드**에 다른 형식의 HTTP(S) 직접 링크가 있는 경우에만 그 링크를 안내합니다. 다른 형식은 동일 파일이 아니며 실제 접근 성공은 확인 전입니다. 링크 목록 저장에는 직접 링크로 선택한 파일만 들어갑니다.
- 대체 링크가 없거나 원본 제품을 확인하려면 Sentinel-2는 [Copernicus Browser](https://dataspace.copernicus.eu/browser/), Landsat는 [USGS EarthExplorer](https://earthexplorer.usgs.gov/)에서 Item ID·촬영일·제품을 직접 확인하세요. 포털 계정 또는 별도 이용 조건이 적용될 수 있습니다. 앱은 포털 검색이나 파일 다운로드를 대신 수행하지 않습니다.
- Sentinel-1은 앱 내 STAC 검색을 지원합니다. GRD 원본은 CDSE 계정 인증이 필요하며 파일 링크만으로 다운로드/전처리를 보장하지 않습니다. 제한 Asset의 Copernicus Browser 경로는 보조 접근 안내입니다.

### 미리보기와 원본 파일의 접근 확인

미리보기는 화면에 보이면 자동으로 요청하며 실제 이미지를 모두 받아 형식을 확인한 경우에 표시/이미지 저장을 활성화합니다. 실패 시 명시 재시도를 제공합니다. `선택 원본 접근 확인`과 `원본 다운로드`는 별도이며 원본은 사용자가 눌러야 수신합니다. Asset 누락·미지원 형식·404·401/403·앱 설정 없음·requester-pays·USGS 로그인·시간/크기 상한을 구분합니다. 일반 403만으로 EULA가 원인이라고 단정하지 않습니다.

Landsat는 Earth Search의 전체 제품 ID·플랫폼·촬영일·수준·Collection 버전·파일명을 USGS 공식 Item과 대조합니다. 검증한 L2SP 표본은 미리보기 Asset이 있지만 S3 requester-pays이며, 동일 파일의 USGS 경로도 302 로그인 이동이었습니다. 이를 이미지 없음이나 NASA 로그인 필요로 표시하지 않습니다. EarthExplorer에서 정확한 전체 제품 ID로 찾는 절차를 제공합니다. 비용 동의 없이 AWS 접근을 우회하거나 다른 장면 파일을 연결하지 않습니다.

NASA VNP09GA.002 공개 browse 표본은 전체 JPEG 수신을 확인했습니다. 원본 파일은 사용자별 Earthdata 권한이 필요하며 실제 인증 검증 전에는 다운로드 성공으로 표시하지 않습니다. 토큰·인증 헤더·최종 서명 URL은 브라우저로 전달하지 않습니다. [실제 Item·원인·제한](docs/PROVIDER_MEDIA_ACCESS.md)을 확인하세요.

### 지도의 레이어와 자연어 연결

- `실제 Item 촬영 범위`는 STAC geometry이며 유효 픽셀 범위가 아닙니다. `선택 영상 원본 미리보기`는 제공처 이미지를 별도 패널에 표시하며 지도에 정합된 정량 래스터가 아닙니다. 이미지가 없거나 접근에 실패해도 검색 Item·원본 링크는 남습니다.
- `실제 AOI 품질 마스크`는 A3/A4 픽셀 검사가 반환한 장면에서만, `실제 처리 결과`는 A4 NDVI 차이 계산이 반환한 비교 쌍에서만 활성화됩니다. 선택형 ML 추정 작업이 끝나면 **목표일 실제 관측 픽셀**과 **모델 추정 픽셀**의 거짓색 레이어를 별도로 켤 수 있습니다. 지도 PNG는 화면 미리보기이며 정량 값·정확한 격자/픽셀 종류는 결과 GeoTIFF와 `pixel_status.tif`에서 확인합니다. 분석하지 않은 장면에는 빈 레이어나 가짜 값을 만들지 않습니다.
- 장면 선택 이후 `다음 작업`에서 원본·밴드·다운로드, 비교, 지원되는 QA/분석을 선택합니다. 접힌 `다른 작업 요청`은 기존 목적을 유지하며 지원하는 표현만 실행합니다. 예: `현재 조건으로 검색해` → 동일 검색, `선택한 두 날짜를 비교해` → 비교 열기, `이 지역으로 이동해` → 확정 AOI로 이동, `이 영상은 구름이 많아` → 품질 대응 안내. 미지원 요청은 설명하고 실행하지 않습니다. 본문으로 AOI·기간을 바꾸지 않습니다.
- NASA HLS S30/L30 및 GIBS 미리보기는 이번 연결에 포함되지 않았습니다. [HLS 후속 설계](docs/HLS_ADAPTER_DESIGN.md)에 제품·미리보기·원본 접근을 분리해 기록했습니다. 참고 저장소의 최근 30일·장면 구름 20% 기본값을 현재 분석 정책으로 복사하지 않았습니다.

검색 결과는 목적에 따라 추천한 컬렉션의 후보입니다. 부적합 영상이 모두 제거된 목록이 아니며 구름·유효 픽셀 검사 전 분석 가능성을 확정하지 않습니다. 침수 목적에서는 Copernicus Sentinel-1 GRD도 실제 검색합니다. SAR 전처리·침수 분석은 미지원이며 광학은 맑은 시기의 보완 자료입니다.

### 탑재체·센서 카드의 의미

- 식생·녹지/도시: Sentinel-2 MSI와 Landsat 8 OLI / Landsat 9 OLI-2의 지표반사도 제품을 추천합니다. 필수 밴드와 다운로드 기본 선택은 모두 `backend/app/purpose_plan.py`의 기존 규칙을 사용합니다.
- 홍수·장마: Copernicus Sentinel-1 C-SAR GRD를 실제 검색합니다. SAR 전처리·침수 계산은 미지원입니다. 광학 두 후보는 맑은 시기 **조건부 보완**이며 구름 중 관측 필수 조건을 충족하지 않습니다.
- 열환경: Landsat 8 TIRS / Landsat 9 TIRS-2의 **L2SP 지표온도 ST_B10**만 직접 후보로 추천합니다. 연결된 Earth Search Asset은 `lwir11`입니다. L2SR·제품 정보 누락·열 밴드 누락은 카드 검색에서 제외합니다. 원관측 100 m와 재표본화 출력 30 m를 구별하며 지표온도를 기온이라고 하지 않습니다. Sentinel-2는 직접 LST 대안이 아닙니다. 이 ST 제품은 야간 요구를 충족하지 않습니다.
- 관측 조건 충족, 앱 검색/처리/다운로드 지원, AOI·기간 가용성, 선택 장면 픽셀 QA를 따로 표시합니다. 가용성은 미검색/검색됨/없음/검색 실패입니다. 미조회 범위가 있으면 0건을 없음으로 확정하지 않습니다. A3를 실행하기 전에는 **미검사**이며, 실행 후 해당 AOI 장면의 진단 결과 또는 실패를 연결합니다. 센서 자체의 품질 판정은 아닙니다. Asset 링크 제공은 인증 불필요·파일 접근 보장이 아닙니다.
- 대상 폭이 필수 밴드 최대 원관측 간격의 3배보다 작으면 조건부로 안내합니다. 이는 앱의 보수적인 운영 가정이며 보편적 과학적 식별 기준이 아닙니다. 한 픽셀이 곧 객체 식별 가능 크기가 아닙니다. SAR 격자는 실제 Item 메타데이터가 제공한 경우에만 표시하며 유효 해상도로 간주하지 않습니다.
- 규칙 `sensor-purpose-2026-10-30.2`, 현재 등록 검토일 `2026-10-30`. 데이터 전용 카탈로그 `backend/app/sensor_catalog.py`와 기존 추천 엔진 `recommendations.py`를 사용하며 실행 중 웹/LLM 호출은 없습니다. 사양·출처는 생성하지 않습니다.
- 카드 검색에서 제외된 메타데이터 후보 수는 컬렉션 상태의 `filtered`로 표시합니다. 제외 후보는 반환 할당량을 소모하지 않으며 기존 요청/시간 상한 내에서 다음 페이지를 조회합니다. 직접 선택 검색은 참고 후보도 포함하므로 별도 가정을 표시합니다.

## 5. 실제 데이터와 제한

### 제한된 “구름이 너무 많아” 후속 흐름

기존 요청 화면은 목적·지도에서 확정한 AOI·UTC 기간·선택 장면을 구조화해 보여 줍니다. 식생 **한 시점/기간 상태**의 공개 Sentinel-2 L2A 작은 AOI에 한해 선택 영상 또는 같은 위성 플랫폼·제품의 기간 내 후보를 실제 SCL/필수 밴드로 검사하고, 사용자가 확인한 계획만 실행합니다. 최대 4장면·31일·A3의 25 km²/100,000셀/64 MiB/60초/동시 1작업 상한을 적용합니다. 픽셀마다 실제 한 관측의 모든 밴드를 함께 선택하며 원본 날짜·장면 인덱스, 남는 결측, 유효 마스크, GeoTIFF와 manifest를 ZIP으로 제공합니다. 이는 **여러 날짜의 실제 관측 선택 합성**이고 한 날짜 촬영 영상이나 ML 복원이 아닙니다. 전후 사건·생육 변화 분석의 날짜 혼합, 기간 밖 자료, 지원하지 않는 센서/제품은 차단합니다. 대규모 AOI, 다른 목적, 다중 서버 작업 관리는 지원하지 않습니다. 검색/계획/실행에서 제공처 접근 실패 시 가짜 결과로 대체하지 않습니다.

### 선택형 ML 추정영상 — 실측과 분리

`다음 작업`에서 구름 대응을 요청하거나 실제 AOI 품질이 저하된 경우에만 품질 해결 흐름이 나타납니다. 같은 기간의 다른 실제 영상을 먼저 확인하고, 확인 체크 후 실제 관측 합성 계획을 검사합니다. 원본 픽셀 검사로 합성 후에도 결측이 남는다고 확인되고 식생 한 시점 Sentinel-2 L2A 조건을 만족하면 접힌 `3. 남은 결측 · 실험적 ML 추정 (선택)`을 열 수 있습니다. 합성 계획의 결측 근거만으로 진입할 수 있지만 ML 실행에는 별도의 검증·사용자 확인이 필요합니다. **ML 추정영상 모드**는 관측 픽셀 선택 합성과 별도 버튼·계획 확인·ZIP으로 작동합니다. 식생 한 시점의 작은 AOI에서 같은 Sentinel-2 플랫폼·처리 기준선의 목표 장면과 1~3개 참조 날짜만 사용하며 기간을 넓히지 않습니다. 목표일과 참조일 모두 맑은 픽셀의 적색·근적외선·녹색 반사도 쌍으로 **AOI마다 국소 ridge 회귀**를 학습합니다. 2×2 공간 사분면을 번갈아 보류해 밴드별 MAE/RMSE와 단순 참조일 복사 기준선을 비교합니다. 학습 픽셀·기준선 개선·참조 날짜·값 범위의 운영 조건을 충족할 때만 목표일 가림 영역의 일부를 추정하고, 조건에 맞지 않는 영역은 결측으로 남깁니다.

계획을 확인한 뒤 실행하면 `target_observed.tif`(실제 목표일 관측), `estimated_only.tif`(모델 추정), `estimate_with_observed.tif`(두 종류를 함께 둔 파일), `pixel_status.tif`(0 미해결·1 실측·2 추정), `donor_index.tif`, `donor_date.tif`, `manifest.json`을 내려받습니다. **혼합 파일을 단일 날짜 실측 영상처럼 사용하지 말고 상태 마스크를 함께 확인하세요.** 화면의 검증 오차는 **맑은 보류 픽셀**에서 측정한 값입니다. 불투명 구름 아래 같은 날의 정답을 직접 관측한 정확도가 아니며, 토지피복/생육 변화·구름 그림자 오분류·정합 차이로 실제 가림 영역 오차는 더 클 수 있습니다. 홍수·산불 같은 순간 사건, 전후 변화, 열환경, SAR는 이 모드에서 차단합니다. 정확한 알고리즘·상한·출처·한계와 테스트 상태는 [추정영상 방법 문서](docs/ESTIMATED_IMAGE_METHOD.md)에 기록했습니다. 공개 Sentinel-2 한 사례의 계획→실행→GeoTIFF 재열기는 확인했으나 이 사례만으로 구름 아래 정확도나 다른 지역의 성능을 보증하지 않습니다.

### A3: 작은 AOI의 실제 픽셀 품질 진단

전후 비교에서 **Sentinel-2 L2A의 서로 다른 두 날짜**를 선택한 뒤 아래 `작은 AOI 픽셀 진단`을 누릅니다. 현재 목적·AOI·기간과 A2 기준일을 재사용합니다. 기본 예시 영역은 너무 크므로 좌표를 `[126.70, 36.40, 126.71, 36.41]`로 줄이고 식생 목적, 2025-07-01~31로 검색하면 재현할 수 있습니다. 열환경·Landsat·SAR는 A3 대상이 아닙니다.

기존 `purpose_plan`의 필수 밴드와 SCL만 읽습니다. canonical STAC Item을 재조회하고 실제 GeoTIFF 헤더에서 CRS·해상도·transform·크기·NoData를 확인합니다. 공개 Sentinel COG의 HEAD와 정확한 HTTP 206 범위 응답만 허용하며 전체 GET으로 대체하지 않습니다. 압축 블록 때문에 AOI window보다 더 많은 바이트가 필요할 수 있습니다.

| 상한 | 현재 운영 설정 |
|---|---|
| AOI | 25 km², AOI 중심 LAEA 등적 투영으로 계산 |
| 공통 격자 | 20 m, 최대 100,000셀, CRS·transform·extent·width/height 기록 |
| 원본 읽기 | 밴드 window당 1,000,000픽셀, 압축 블록 4,194,304픽셀 이하 |
| 파일 크기 | 파일당 2,000,000,000바이트, HEAD 크기 누락 시 중단 |
| 전송량·요청 | 작업당 64 MiB, HEAD 포함 128회, 요청당 8초 |
| 시간·동시 작업 | 래스터 자식 프로세스 60초 후 종료, 앱 프로세스당 1개. 사전 Item 조회는 A2의 45초/2 MB 제한을 별도로 사용 |

현재 로컬 단일 서버에서만 검증했습니다. 사용자가 브라우저 요청을 취소해도 서버 작업은 최대 60초 한도까지 진행될 수 있습니다. 멀티워커 배포용 분산 잠금은 없습니다. 상한 초과·네트워크/자료 오류·읽을 픽셀 없음은 **null/미확인**, 실제 관측된 전부 구름은 **검사됨/0%**입니다.

SCL 정책 `s2-l2a-qa-2026-10-29.1`은 식생·수역·도시 목적 모두 SCL 4(식생), 5(비식생), 6(수역)을 관측 유효로 취급합니다. 0(NoData), 1(포화/결함), 2(어두운 영역/지형 그림자), 3(구름 그림자), 7(분류불명), 8~10(구름/권운), 11(눈/얼음), 알 수 없는 분류는 제외합니다. 이것은 목적 대상의 확정 분류가 아니며 눈 분석에 적합하지 않습니다. SCL은 최근접, 연속 밴드는 원본 NoData·SCL 제외 후 평균 재표본화합니다. 유효한 원본 기여율 0.999 이상인 셀만 채택하는 보수적 운영 정책입니다. 10 m를 공통 20 m로 집계하며 업샘플링을 해상도 향상이라고 하지 않습니다.

개별 유효 면적, 공통 촬영 영역 안의 개별 유효 면적, 두 날짜 모두 유효한 면적을 별도로 보여 줍니다. 각 비율의 분모는 AOI 전체 또는 두 시점 공통 footprint 영역으로 명시합니다. LAEA 셀과 AOI/footprint 교집합 면적을 사용해 경계 셀의 부분 면적을 반영합니다. 분류 경계는 20 m 격자 근사이며 SCL 자체의 분류 오류 가능성은 남습니다. 기본 최소 공통 유효율 70%는 사용자가 바꾸는 운영 기준으로, 과학적 분석 가능 판정이 아닙니다.

공식 문서에서 L2A DN=0은 NoData, 반사도는 제품의 scale/offset을 고려해야 함을 확인했습니다. 다만 실제 Earth Search Item에서 `earthsearch:boa_offset_applied=true`와 `raster:bands.offset=-0.1`이 함께 나타나는 제공처 메타데이터 상충을 확인했습니다. 해당 밴드는 보정을 추정하지 않고 **반사도 미확인 / SCL·DN NoData 기반 진단**으로 표시합니다. 파일 기본 scale=1/offset=0도 보정 근거로 추정하지 않습니다. 이 경우에도 SCL·DN 유효 영역은 계산하되 반사도 값이나 지수는 제공하지 않습니다. 파일별 URL·ETag·헤더·window·보정 근거와 처리 정책은 화면 상세에서 확인합니다.

2026-10-29 확인 근거: [Copernicus S2 제품/NoData/보정](https://sentiwiki.copernicus.eu/web/s2-products), [CDSE L2A 밴드·해상도](https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Data/S2L2A.html), [SCL 분류 설명](https://custom-scripts.sentinel-hub.com/custom-scripts/sentinel-2/scene-classification/), [제공처 offset 이슈](https://github.com/Element84/earth-search/issues/71), [Rasterio window 읽기](https://rasterio.readthedocs.io/en/stable/topics/windowed-rw.html). A3 품질 진단은 독립적으로 유지하며 식생 NDVI 변화는 A4 버튼에서만 계산합니다.

### A4: 두 날짜 식생 NDVI 변화와 파일 내보내기

식생 목적, 25 km² 이하 AOI에서 **Sentinel-2 L2A 같은 위성 플랫폼·처리 기준선의 이전→이후 두 날짜**를 선택하고 `두 날짜 NDVI 계산`을 누릅니다. A3의 SCL/NoData 정책·20 m 공통 LAEA 격자·실제 GeoTIFF window 읽기를 그대로 사용합니다. A2 기준일을 입력했다면 이전 촬영일 < 기준일 ≤ 이후 촬영일도 검사합니다. A3 버튼을 먼저 누를 필요는 없습니다. A4가 같은 원본 픽셀 검사를 다시 수행합니다.

필수 밴드는 기존 목적 규칙의 적색 B04와 근적외선 B08, 품질 자료 SCL입니다. STAC scale=0.0001과 처리 기준선·제공처 보정 표시·offset 조합이 공식 L2A 제품 규칙과 일치하는 경우에만 반사도를 계산합니다. 04.00 이전은 보정 미적용·offset=0, 04.00 이상은 보정 미적용·offset=-0.1 또는 보정 적용·offset=0만 허용합니다. **NDVI = (NIR − Red) / (NIR + Red)**, **차이 = 이후 − 이전**입니다. SCL·밴드 NoData·혼합 제외 픽셀을 먼저 제거하고 두 날짜 모두 유효한 셀에만 적용합니다. NaN/Inf, 음수 반사도, 분모 ≤ 0.000001, [-1, 1] 밖의 지수는 제외합니다. 이 수치는 0/0 회피용 수치 경계이며 식생 변화 임계값이 아닙니다. 식생 증가·감소 면적의 분류 임계값은 설정하지 않았습니다.

화면에는 전후 NDVI 면적 가중 평균·평균 차이, 실제 분석 면적, 공통 촬영 영역/AOI 전체에서 제외된 면적과 품질/수치상 제외 이유를 보여 줍니다. 사용자 설정 최소 공통 유효율 70%는 A3의 운영 참고 기준이며 A4 계산을 자동으로 차단하는 보편적 과학 기준이 아닙니다. 계절·생육주기·관측각·대기 조건 차이가 NDVI 차이를 만들 수 있으므로 결과를 식생 증감이나 원인으로 확정하지 않습니다.

`GeoTIFF 2개 + 처리기록 ZIP 저장`에는 `ndvi_change.tif`(float32, 이전/이후/차이 3밴드, NoData −9999), `valid_mask.tif`(uint8, 1=공통 유효, 0=제외/NoData), `processing.json`이 있습니다. TIFF의 CRS·transform·해상도·밴드 설명을 유지합니다. 기록에는 원본 Item/Asset·취득시각·보정값·처리버전·정책·공통 격자·면적·SHA-256이 포함됩니다. 인증정보/서명 쿼리 URL은 기록하지 않습니다. 래스터 경계 셀은 0/1 마스크지만 면적 합계는 AOI·footprint 부분 셀 면적을 반영합니다. 내보내기 ZIP은 브라우저에서 다운로드하며 서버에 결과 파일을 보존하지 않습니다. 압축 ZIP 4 MB 초과는 중단합니다. Next.js 로컬 API 프록시와 브라우저 요청은 각각 120초 제한을 적용합니다. 백엔드는 사전 Item 조회와 격리 래스터 작업에 별도 제한을 적용합니다.

실제 재현 예: AOI `[126.70, 36.40, 126.71, 36.41]`, 2021-07-01~31, `S2B_52SBF_20210716_0_L2A` → `S2B_52SBF_20210726_0_L2A` (같은 03.01 기준선, 보정 표시와 offset=0 일치). 2025년 일부 공개 Item은 `boa_offset_applied=true`와 `offset=-0.1`이 동시에 있어 A4 계산을 보류합니다. 임의 -1000 보정을 적용하지 않습니다. 공식 근거(2026-10-29 확인): [Copernicus L2A 보정·DN=0](https://sentiwiki.copernicus.eu/web/s2-products), [CDSE NDVI B04/B08·SCL 예제](https://documentation.dataspace.copernicus.eu/notebook-samples/openeo/NDVI_Timeseries.html), [CDSE 밴드·해상도](https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Data/S2L2A.html). QGIS 프로그램에서 직접 열어 확인하지는 않았으며 Rasterio/GDAL로 파일의 CRS·NoData·밴드를 다시 열어 검증합니다.

### A2: 두 영상 분석 조건 검사

검색·장면 선택 후 `다음 작업` → `두 장면 비교·분석` → `여러 영상 비교와 해석`에서 `전후 변화용 영상 선택`을 고르면 A2 패널이 나타납니다. 영상 1은 이전, 영상 2는 이후로 선택하고 사건·변화 기준일을 입력한 뒤 `두 영상 조건 검사`를 누르세요. 기준일은 UTC 00:00 경계이며 이전 촬영일 < 기준일 ≤ 이후 촬영일을 검사합니다. 미입력 시 기준일 조건은 미확인입니다. 검색 AOI·기간은 유지합니다.

`POST /analysis-conditions`는 컬렉션·Item ID만 받아 고정 제공처에서 원본을 다시 조회합니다. 기존 목적별 필수 밴드 규칙과 카탈로그의 품질 Asset 목록을 재사용합니다. S2는 SCL, Landsat는 QA_PIXEL/QA_RADSAT, 열환경은 ST_QA(실제 Earth Search 키 qa)도 확인합니다. 누락·다른 제품·동일 Item·역전 날짜·공통 영역 없음에 이유와 다음 행동을 제공합니다.

각 항목은 **통과 / 조건부 / 미확인 / 불가**입니다. 개별 AOI 중첩률과 AOI∩영상1 footprint∩영상2 footprint의 공통 촬영 면적·AOI 대비 비율을 따로 표시합니다. 기존 AOI 중심 LAEA 등적 투영과 경계 0.02도 세분화 방법을 재사용하며, 촬영 범위 근사 면적은 유효 픽셀 면적이 아닙니다.

CRS·shape·transform은 STAC Item/Asset 메타데이터에서 읽고 출처를 남깁니다. Asset 값이 Item 기본값보다 우선합니다. CRS 누락은 위치/타일 이름으로 추정하지 않습니다. transform에서 계산한 격자 간격은 해당 CRS 단위이며 항상 미터라고 표시하지 않습니다. 서로 다른 밴드·시점 격자는 정합 필요로 안내합니다. **래스터 파일 헤더는 읽지 않았습니다.**

공개 Asset은 HTTP HEAD 응답만 확인합니다. 파일 본문·픽셀을 읽거나 다운로드하지 않으며 HEAD 성공은 파일 무결성/픽셀 품질 보장이 아닙니다. 요청자 비용·S3·인증/서명 URL·등록되지 않은 호스트는 미확인으로 남깁니다. 자동 인증·비용 동의·리다이렉트 추적은 없습니다. 현재 확인한 공개 호스트는 sentinel-cogs.s3.us-west-2.amazonaws.com, landsatlook.usgs.gov, usgs-landsat.s3.us-west-2.amazonaws.com입니다. 실제 Landsat 요청자 비용 Asset은 접근하지 않습니다.

검사 1회당 최대 14회 요청(원본 Item 2개와 필요한 Asset HEAD), 네트워크 총 45초, 요청당 8초, Item 본문 2 MB 상한입니다. 한 검사 안에서는 순차 요청하며 재시도하지 않습니다. 시간 초과/접근 오류는 미확인 또는 현재 접근 불가이고 0%가 아닙니다. 영상·기준일·검색 입력 변경 시 이전 검사 결과를 폐기합니다. A3 픽셀 진단은 별도 버튼으로 실행합니다. A2 결과는 메타데이터 검사로 유지하며 두 검사 근거를 혼동하지 않습니다.

메타데이터 해석 근거: [STAC Projection Extension](https://github.com/stac-extensions/projection) (2026-10-29 확인). 검사 버전은 a2-conditions-2026-10-29.1입니다.

- 검색 제공처: [Element 84 Earth Search v1](https://earth-search.aws.element84.com/v1)
- 실제 확인한 컬렉션: [`sentinel-2-l2a`](https://earth-search.aws.element84.com/v1/collections/sentinel-2-l2a), [`landsat-c2-l2`](https://earth-search.aws.element84.com/v1/collections/landsat-c2-l2)
- 2026-10-28 컬렉션 목록과 실제 검색을 확인했습니다. Earth Search에 Sentinel-1 컬렉션이 존재하더라도 **이 앱에서는 향후 지원 예정**입니다.
- A1 검색은 기존 설치된 `httpx`로 STAC `/search` 및 `next` 링크의 GET/POST·body·merge를 명시적으로 처리합니다. 컬렉션별 최신순 25건 페이지를 확보하고 각 컬렉션에서 1건씩 교대로 전체 상한까지 반환합니다. 빈 결과·실패로 남은 몫은 다른 컬렉션에 사용합니다. `(collection, id)`로 중복을 제거하며 지도·비교·밴드 상태도 같은 복합 식별자를 사용합니다. 다른 컬렉션의 같은 ID는 보존합니다. 전체 카탈로그 최적 순위가 아닙니다.
- 컬렉션마다 성공·빈 결과·부분 성공·실패·조회 제한·미조회와 사유, 반환/확보 건수, 미반환 버퍼, 중복/형식 오류, 요청 횟수, 마지막 확보 시각을 표시합니다. `has_more=null`은 미확인입니다. 마지막 확보 시각은 재개 커서가 아닙니다. 상한에서 잘린 정확한 남은 총수는 미확인이고, 범위를 줄이거나 특정 위성으로 재검색하세요.
- 일부 실패에도 확보한 실제 결과를 유지합니다. 성공 컬렉션이 빈 결과이고 다른 컬렉션이 실패한 경우 전체 0건으로 확정하지 않습니다. 전부 실패 시 HTTP 502(전부 timeout이면 504)와 컬렉션 상태를 반환하고 UI가 전체 실패로 표시합니다. 조회를 정상 완료한 0건만 빈 결과입니다. 두 컬렉션은 모두 Earth Search에 연결되므로 독립 제공처 이중화는 아닙니다.
- 최대 기간 366일, 경도·위도 폭 각각 5도, 위도 -80~80. 날짜 변경선 횡단 AOI는 지원하지 않습니다.
- 검색당 STAC 요청 최대 12회, 전체 네트워크 대기 deadline 45초, 개별 요청 전체 대기 최대 10초(연결 최대 5초), 자동 재시도 없음. 남은 deadline을 다음 요청에 적용합니다. 로컬 JSON·기하 계산에는 소량의 추가 시간이 걸릴 수 있습니다. 브라우저 제한은 120초입니다. 수신한 결과를 버리지 않고 제한·실패·미조회 상태를 반환하며 가짜 데이터로 대체하지 않습니다.
- 서버에 검색 결과를 저장하지 않습니다. 재검색은 제공처의 최신 상태를 사용하므로 결과가 달라질 수 있습니다.

## 6. 예비 평가의 의미

**분석 가능 여부는 모든 영상에서 `판정 보류`입니다.** 검색 순위와 A2는 메타데이터 기반이고, A3만 실제 파일 헤더·SCL·필수 밴드를 읽습니다.

- 촬영 시각, 센서, 장면 구름량, 제품 유형은 Item 메타데이터 그대로 사용합니다. 누락은 `미제공`으로 표시합니다.
- 해상도는 Item/Asset의 `gsd` 및 `raster:bands.spatial_resolution`에 제공된 값입니다. 여러 해상도는 모두 표시하고 Asset별 값도 펼쳐 볼 수 있습니다. 센서 고유 해상도와 제품 격자 간격이 혼재할 수 있으며, 특히 열 밴드의 재표본화 격자 간격을 센서 고유 분해능으로 해석하면 안 됩니다.
- AOI 중첩률 = `AOI ∩ Item geometry의 면적 / AOI 면적 × 100`. AOI 중심의 Lambert Azimuthal Equal Area 투영과 Shapely를 사용하며 투영 전 0.02도 간격으로 경계를 세분화합니다. 기하 연산의 근삿값이지 구름 없는 유효 픽셀 관측률이 아닙니다.
- 전체 장면 `eo:cloud_cover`는 AOI 구름량으로 바꿔 해석하지 않습니다.
- 카드의 날짜 차이는 검색 시작일과 촬영일의 달력 날짜 차이입니다. 전후 선택 안내는 메타데이터의 취득 시각 순서만 검사합니다. A2 버튼은 기준일·Asset 접근, A3 버튼은 소형 AOI의 공통 격자·유효 픽셀을 별도로 검사합니다.
- 센서 그룹은 식생·도시·침수 광학 보완=Sentinel-2, 열환경=Landsat의 고정 탐색 순서입니다. 밴드 누락이 있어도 센서 그룹은 유지합니다. 영상은 그룹과 독립적으로 필수 밴드 확인(확인→미충족→메타데이터 미제공) → AOI 기하 중첩 내림차순 → 전체 장면 구름량 오름차순 → 제공 해상도 최솟값 → 시작일 차이 → 컬렉션·ID 순으로 정렬합니다. 수치 누락은 해당 기준의 마지막입니다. 그룹 안에서는 이 순서를 유지합니다. 픽셀 품질 점수나 과학적 적합성 판정이 아닙니다.
- 열환경은 열적외선 common_name, 식생은 적색·근적외선 common_name을 확인합니다. 밴드 존재는 실제 접근 가능성·픽셀 유효성을 보장하지 않습니다.
- 제공처 원본 미리보기는 thumbnail Asset이 제공될 때만 표시합니다. 접근 실패 시 실패 문구를 표시하며 대체 썸네일을 만들지 않습니다. A3/A4의 별도 지도 PNG는 실제 픽셀 작업에서만 생성합니다.

브라우저 테스트는 설치된 Microsoft Edge를 헤드리스로 실행합니다. 첫 테스트는 실제 STAC 검색이며 요청을 가로채지 않습니다. `search.spec.ts`의 오류 테스트 및 `reliability.spec.ts`는 `TEST_ONLY_SYNTHETIC` 응답·API 지연/실패를 모사합니다. 링크 파일 검증은 실제 브라우저 다운로드 결과를 읽지만 합성 공개 URL을 사용하며 실제 영상 파일은 다운로드하지 않습니다. 합성 fixture는 앱 실행 경로에서 사용하지 않습니다. 자세한 검증 기록은 `TEST_REPORT.md`에 있습니다.

## 9. 문제 해결

- `python` 또는 `npm`을 찾지 못함: 해당 프로그램을 설치한 후 PowerShell을 새로 열어 주세요.
- PowerShell 스크립트 실행 제한: `npm` 대신 문서의 `npm.cmd`, 가상환경 활성화 대신 `.venv\Scripts\python.exe`를 사용합니다.
- `서버에 연결할 수 없습니다` / 502: 백엔드 창이 실행 중인지, 8000 포트가 맞는지 확인합니다. 다른 프로그램이 포트를 사용하면 임의로 종료하지 말고 포트를 변경하세요.
- API 실패·지연: 인터넷 연결과 Earth Search 상태를 확인하고 기간·범위를 줄여 재검색합니다.
- 지도 초기화 실패: WebGL·브라우저 하드웨어 가속 설정을 확인하세요. 지도 타일 오류와 위성 검색 오류는 서로 별개입니다.
- 개발 서버를 종료한 뒤 빌드에서 `.next/dev/types` 오류가 발생하면 `frontend` 폴더의 자동 생성 캐시 `.next/dev`만 삭제한 후 `npm.cmd run build`를 다시 실행하세요. 소스 파일은 삭제하지 않습니다.
- 결과 없음: 해당 컬렉션에 실제 영상이 없는 조건일 수 있습니다. 특히 오래된 날짜나 촬영 간격에 주의하세요.
- `미제공`: 제공처가 해당 메타데이터를 제공하지 않은 상태입니다. 임의 값으로 대체하지 않습니다.

## 10. 완료 및 후속 단계

A1 이후 자동 착수하지 않습니다. 사용자 지정 단계만 이어서 개발합니다. 단계별 상세 범위·완료 기준은 [개발 계획](docs/NEXT_STEPS.md)을 따릅니다.

- A2 완료: 전후 기준일·동일 센서/제품·필수/품질 밴드·HTTP HEAD 접근·날짜·CRS/격자 메타데이터 검사. 기하 공통 영역과 개별 AOI 중첩 구분. 파일 헤더 미검사·픽셀 미검사·분석 판정 보류.
- A3 완료: 접근 가능한 Sentinel-2 L2A의 작은 AOI 두 날짜만 실제 범위 읽기, 제품 scale/offset/NoData와 버전별 SCL 정책, 공통 격자·공통 유효율. 고정 소형 래스터 기대값과 실제 사례로 재현.
- A4 완료: Sentinel-2 L2A 같은 플랫폼 두 날짜의 공통 유효 픽셀에서 식생 NDVI 전후·차이·면적·마스크를 계산한다. GeoTIFF 2개와 처리 기록 JSON을 ZIP으로 내보내며 수치 경계를 검사한다.
- A5: 독립된 Sentinel-1 공식 API·제품·접근성 조사 후 검색/메타데이터/Asset 접근만 지원. SAR 전처리·침수 판정·광학 융합은 별도.

현재 다운로드 직접 링크·목록 저장, 날짜별 지도 탐색, 메타데이터 비교, A3 소형 AOI 픽셀 진단과 A4 식생 NDVI 차이·GeoTIFF 내보내기, 제한된 실제 관측 픽셀 선택 합성과 별도의 선택형 ML 추정 모드가 구현되어 있습니다. ML은 고정 TIFF fixture와 공개 Sentinel-2 한 사례의 전체 실행에서 검증했으며 구름 아래 참값의 정확도는 미검증입니다. HLS 검색/GIBS 미리보기와 A5 SAR 검색은 미구현이며 자동 진행하지 않습니다.

구름 탐지·실관측 합성·AI 복원의 정확도 차이와 관련 원저·학회 발표는 [구름 제거 문헌 조사](docs/CLOUD_REMOVAL_LITERATURE.md)에 정리했습니다. 실제 합성을 단일 날짜 복원으로 해석하지 마세요.
