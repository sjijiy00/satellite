# 자연어·지명·행정경계 AOI (2026-11-02)

> 현재 계약(2026-11-02): 아래의 과거 규칙/AI 버튼/수동 영역 적용 흐름은 [AI 중심 조건 입력](AI_PRIMARY_INPUT.md)으로 대체했습니다. 기본·실패 경로에서 규칙 추출을 사용하지 않으며 명확한 AI+실제 위치/경계 결과를 자동 AOI에 반영합니다. 아래는 이전 구현의 출처·설정·설계 이력입니다.

## 화면에서 확인하는 순서

1. `2025년 8월 서울시 지표면 온도 알고싶음`을 입력하고 잠시 기다린다. 무료 규칙 해석은 UTC 2025-08-01~2025-08-31, 열환경/지표면 온도, 서울시를 추출한다. OpenAI는 기존 명시 버튼에서만 호출한다.
2. 지명 추출 완료 → Kakao 조회 중/후보 선택 필요 → 위치 확인 완료 → 행정경계 제안 완료를 구분한다. Kakao 설정 준비됨은 실제 조회 성공이 아니다. AI 결과가 없어도 조회한다. `지명 직접 입력`도 같은 API를 사용한다.
3. 서울이 정확히 확인되면 지도는 서울 경계에 맞춰 이동하고 주황 점선의 **미확정 경계 제안**을 표시한다. 날짜·목적만 먼저 반영하고 기존 AOI/좌표는 유지한다. 중심점 주위에 임의 사각형을 만들지 않는다.
4. 경계 출처·시점·좌표계·면적·서남동북 좌표를 읽고 `이 영역 적용`을 누른다. 좌표 입력·지도 bbox·기존 검색 API는 동일한 외접 bbox를 사용한다. 파란 실선은 적용한 경계 참고, 녹색 사각형이 **실제 검색 범위**다.
5. 기존 추천 제품을 확인하고 검색 버튼을 누른다. 제안·날짜 변경만으로 위성 검색, 원본 다운로드, 픽셀 처리, 유료 AI를 자동 실행하지 않는다.

직접 수정한 날짜/목적은 이후 응답으로 덮지 않는다. 날짜 등은 충돌 안내의 `문장에서 다시 적용`으로 갱신한다. AOI는 `이 영역 적용` 또는 직접 지도/좌표 확정으로만 교체한다. 좌표를 직접 고치면 적용했던 경계와의 연결을 해제하고 다시 확정하도록 한다. 기존 값은 제안이 도착한 이유만으로 삭제/축소하지 않는다.

## 서울 경계의 출처와 가공

- 공식 원자료: **국가데이터처 SGIS 행정구역 통계 및 경계**, [공공데이터포털 15129688](https://www.data.go.kr/data/15129688/fileData.do).
- 기준: 원본 DBF `BASE_DATE=20250630`, `SIDO_CD=11`, `SIDO_NM=서울특별시`. 원본 파일 `bnd_sido_00_2025_2Q`의 서울 레코드만 사용했다. 2024년 통계와 묶여 있지만 **경계 자체는 2025년 2분기** 자료다.
- 이용 조건: 포털의 **이용허락범위 제한 없음**, 무료 제공 표시를 2026-11-02 원문 HTTP200으로 확인했다. 출처를 표시하며 SGIS 통계서비스용 경계임을 알린다. 법적 측량/최신 법정경계 확정 자료라고 표시하지 않는다.
- 원본 `.prj`: Korea 2000 / Unified CS, **EPSG:5179**, 미터. pyproj의 `always_xy=True`로 **EPSG:4326, 경도·위도 순서**로 변환했다. 원본 꼭짓점과 홀/다중 폴리곤을 유지했고 간소화하지 않았다.
- 검증: 원자료 컴포넌트/전체 ZIP/생성 GeoJSON SHA-256, 코드·이름·날짜, geometry validity, 서울 좌표 범위, 경계에서 다시 계산한 bbox, 서울 중심점 포함을 확인한다. 원본 CRS 면적은 **605.3012246 km²**다.
- bbox `[서,남,동,북]`: `[126.76448395994285,37.42829747715147,127.18379492887969,37.70145527232949]`. 외접 사각형 면적은 지역 중심 LAEA 계산 약 **1123.12 km²**다. 경계 면적과 사각형 면적은 다르다.

결과는 `backend/app/data/boundaries/seoul-sgis-2025-q2.geojson`, 원본 URL/라이선스/CRS/해시는 같은 이름의 `.metadata.json`에 있다. 재현하려면 포털에서 공식 ZIP을 받고 `.venv\Scripts\python.exe scripts/import-seoul-boundary.py <공식 ZIP 경로>`를 실행한다. 스크립트는 입력 ZIP의 ESRI Polygon/DBF만 읽으며 다른 형식·예상 밖 CRS·행정명/면적은 거부한다. 실행 중 서비스가 원자료를 다시 다운로드하거나 새 계정/키를 발급하지 않는다.

## 위치 검색과 정확한 매칭

규칙과 AI의 추출 지명, 직접 입력은 `POST /places/search {place}`로 합친다. 문장 전체를 브라우저에서 위치 API에 보낼 필요가 없으며 Kakao에도 추출한 지명만 전송한다. 기존 `{text,place}` 호출은 호환되지만 `text`는 Kakao에 전달하지 않는다. REST 키는 기존 서버 환경의 고정 HTTPS Authorization 헤더에만 사용한다. 설정이나 인증키는 변경하지 않는다.

서울·서울시·서울특별시는 등록 별칭으로 정규화한다. Kakao REGION의 행정 단계(시도)·상위 지역·제공된 행정 코드(등록한 `11` 또는 `1100000000`과 정확히 일치)·중심점 포함 여부를 함께 대조한다. 서울의 구/동 또는 다른 지역을 서울 전체로 바꾸지 않는다. 코드가 제공되지 않으면 정확한 시도 이름·단계/상위 지역·중심점 포함을 대조하고 공식 SGIS 코드11을 경계 출처와 별도로 표시한다. `region_code`를 제공처가 준 것처럼 생성하지 않는다.

중구/광주 등 후보는 이름·전체 주소·상위 지역·행정 단계를 보여 주고 사용자가 선택한다. 문장에 서로 다른 지역이 있으면 검색할 한 지역을 먼저 고른다. 0건·서비스 장애·시간 초과·요청 제한·설정 누락을 구별하며, 없다는 이유로 임의 좌표/부모 구역으로 대체하지 않는다. 경계가 미등록/검증 실패면 확인된 점 위치로 지도만 이동하고 수동 AOI를 안내한다.

입력 안정화 800ms, IME 중 조회 금지, 취소/문장·후보 세대 검사, 수동 지도/AOI 수정 세대 검사, 기존8초 서버/9초 클라이언트 상한을 사용한다. 같은 문장·지명의 진행 중 요청은 합치고 현재 화면에 표시 중인 결과/오류·후보를 잃지 않도록 재사용한다. 60초 요청 키로 반복 blur를 억제하며 실패는 명시 조회로 재시도한다. 추출 캐시10분과 공식 경계 모듈 캐시를 사용한다.

**Kakao 결과를 새 서버 캐시·DB·localStorage·다운로드 manifest로 보관하지 않는다.** 현재 표시용 일시 상태만 유지한다. 이는 Kakao 담당자의 [실시간 서버 경유/MapLibre 사용 답변](https://devtalk.kakao.com/t/api/152137)과 [결과 저장 제한 답변](https://devtalk.kakao.com/t/local-api-geocoding/151848)을 고려한 범위다. 상세 API·계정별 쿼터는 [공식 Local 문서](https://developers.kakao.com/docs/ko/local/dev-guide)를 따른다. 캐시 요구를 Kakao 응답의 영속 축적 허용으로 해석하지 않는다.

## 지원 범위와 처리 한계

이번에 **폴리곤 제안까지 등록한 지역은 서울특별시 전체 한 곳**이다. 파일/코드/출처를 등록하고 동일 검증을 거쳐 다른 시도·시군구로 확장할 수 있다. 전국 모든 경계를 이미 지원한다고 주장하지 않는다. 기존 충남·상주·영천 자료는 출처가 있는 로컬 카메라 참고로 유지하며 최신 경계 폴리곤으로 취급하지 않는다. 영천군의 옛 지명 안내도 유지한다.

현재 검색 API는 bbox만 받는다. **행정경계 외접 범위**로 검색하며 다른 지역도 포함된다. **경계 폴리곤 클리핑은 미구현**이고 서울시 경계로 잘라 분석했다고 표현하지 않는다. bbox 크기는 기존 검색 검증(가로/세로5도 이하) 안이지만, 서울 전체는 기존 S2 실제 픽셀 처리의 **25 km²** 제한을 넘는다. 작은 AOI로 직접 줄여야 하며 앱이 몰래 줄이지 않는다. 기존 열환경 추천은 Landsat 열적외선 제품 탐색이다. 서울 전체 지표면온도 계산 엔진이나 Landsat 픽셀 분석을 새로 구현하지 않는다.

## 검증의 경계

기본 검증은 공식 로컬 경계 + mock Kakao/AI 응답으로 수행한다. E2E 기본 transport는 Kakao 조회를 차단하고 각 테스트가 명시 fixture를 제공한다. 실제 사용자 Kakao 쿼터·유료 AI를 사용하지 않는다. 원자료의 실제 다운로드/좌표 검증과 Kakao 실조회 성공은 다른 근거다. 실제 Kakao 검색은 이번 작업에서 수행하지 않았으며 필요하면 대상·횟수를 먼저 알린다. 최신 명령·종료 코드·실패와 통과·실행 반영 여부는 [TEST_REPORT](../TEST_REPORT.md)를 따른다.
