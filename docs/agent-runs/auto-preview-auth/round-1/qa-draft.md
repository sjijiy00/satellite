# QA 초안 — 자동 미리보기

상태: 테스트 초안 작성 및 TypeScript 구문 확인만 완료. 통합 구현 전이며 E2E 실행, 빌드, 서버 실행 및 최종 검증은 하지 않았다.

- `frontend/tests/auto-preview.spec.ts`: TEST ONLY 합성 검색, 미디어 세션·inspect·이미지 응답. 자동 이미지와 원본 요청 부재/중복, viewport 밖 대기, 실패 후 수동 재시도, 409 세션 복구, receipt 404 복구 제한, 장면 변경의 늦은 응답, 모바일 너비를 검증하도록 작성했다. 실제 NASA/USGS/CDSE 인증이나 제공처 접근 성공의 증거가 아니다.
- 구문 확인: `typescript.transpileModule` diagnostics 0, 종료 코드 0. 타입 검사나 브라우저 동작 통과를 의미하지 않는다.
- 기존 `ProviderPreview.tsx`의 `.imagery-preview`, 재시도 버튼 및 `media-access.spec.ts` fixture 패턴과 리더 계획의 session/409 응답 계약을 기준으로 작성했다. 병행 구현에 따라 선택 상태, 공유 캐시, 404 오류 표시 및 재시도 횟수에 관한 실제 동작을 통합 후 확인해야 한다. 특히 카드와 상세가 둘 다 가시적인 상태에서 한 요청인지 별도로 확인할 필요가 있다.
- 인증 변경 중 지연 응답 폐기 시나리오는 인증 generation 갱신 이벤트와 UI 계약이 병행 구현 중이라 아직 테스트하지 못했다. 장면 전환 테스트도 대기 요청이 실제 시작됐는지 통합 후 확인·보강해야 한다. 외부 제공처 요청을 보장 없이 허용하지 않도록 테스트 실행 환경의 네트워크 차단을 확인하고, 기타 앱 API는 기존 로컬 환경에 의존할 수 있으므로 완전한 네트워크 격리도 통합 QA에서 보강해야 한다.
- 실제 `.env`, 기존 테스트와 제품 코드는 수정하지 않았다. 전문 스킬·위임 사용 없음.
