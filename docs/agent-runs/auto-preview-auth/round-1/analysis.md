# Analyst — 회차 1 판정과 회차 2 권고

## 요구별 판정

- **자동 미리보기: 부분 완료.** 가시성 기반 공유 큐, 동시 2개, preview 전용 요청과 제한된 재시도는 구현됐다. 원본 전송은 명시 동작이다. 실제 브라우저 표시와 요청 수는 검증되지 않았다.
- **로그인 유지: 부분 완료, 보안 수정 필요.** NASA의 로컬 DPAPI 저장·갱신은 구현됐으나 현재 Windows 기본 활성이고 폐기 실패 후 재시작 복원 위험이 있다. 실제 ACL 준비와 NASA 로그인·갱신·파일 권한은 미검증이다. 무기한 연결은 보장되지 않는다.
- **여러 제공처: 부분 완료.** 기존 공개 검색은 3개 제공처·4개 컬렉션이다. USGS/CDSE 신규 원본 인증은 미연결이며 NASA 설정도 없다. 검색 지원을 인증·원본 접근 완료로 표현하지 않는다.
- **Kakao: 실제 키 조회 성공, 앱 반영 미완료.** 최신 리더 점검은 공식 API HTTP 200, REGION 1건을 확인했다. 토론 및 QA의 실조회 미검증 문구는 해당 역할 당시 기록이다. 실행 서버 설정은 여전히 미반영이며 UI 카메라 이동과 AOI 확정은 미검증이다.

## 합의와 판정

A/B는 폐기 실패, 503 상태 처리, 검증 보류에 합의했고 상호 응답에서 실질적 이견은 없다. 코드상 `delete` 실패는 현재 인스턴스만 불가로 만들고 logout은 503에도 cookie를 삭제한다. 재시작 후 남은 grant가 복사된 SID로 복원될 위험은 코드 결함이며 실제 악용 재현은 아니다. 503 뒤 SID 없는 재시도 성공은 이전 grant 폐기의 증거가 아니다. 로컬 grant 폐기와 NASA 측 철회도 별개다.

독립적 내구성 폐기 기록 또는 DB 격리는 **기록·격리가 실제 성공하고 이후 복원 전에 검증되는 경우에만** 재시작 차단 근거가 된다. 모든 지속 쓰기와 제공처 철회가 실패하면 영구 폐기를 보장할 수 없다. 실패를 명시하고 확인 가능한 저장소 격리·복구와 제공처 측 철회를 안내한다. DNS 재해석은 미재현 가설로 후속 검토한다.

## 회차 2 필수 수정 지시

1. **Auth/보안:** `EARTHDATA_PERSIST_SESSIONS=1` 명시 opt-in만 영속 저장·복원을 허용하고 기본은 메모리로 전환한다. 기본값 변경만으로 기존 DB가 폐기되는 것은 아니다. 과거 DB가 남아 있거나 상태를 확인할 수 없으면 opt-in 재활성화에서 기존 grant를 복원하지 않도록 확인 가능한 격리·초기화 절차를 설계하고 실패 시 fail-closed한다. 폐기 기록이나 격리가 쓰기 실패에도 항상 성공한다고 주장하지 않는다. 503과 폐기 미확인 의미, 운영자 조치와 제공처 철회 구분을 문서화한다. 단일 프로세스·공개 callback 제한을 유지한다.
2. **Frontend:** logout 503의 `storage_disposed=false`를 구체적으로 표시하고 현재 인증 표시·미리보기/원본 캐시 및 진행 요청을 무효화하며 다른 탭에 통지하고 상태를 재조회한다. 재조회나 cookie 없는 재시도 결과를 이전 폐기 성공으로 바꾸지 않는다. 명시 재시도와 불확실한 폐기 안내를 유지한다.
3. **QA/보안:** 삭제 실패→권한 복구→재시작→복사 SID, opt-in 재활성화와 기존 DB, 갱신 중 logout, 503 후 탭·큐·지연 응답 및 SID 없는 재시도를 검증한다. 성공 가능한 격리와 모든 쓰기 실패를 각각 시험한다. 가시성·동시 상한·중복·인증 변경·원본 자동 요청 0 및 명시 다운로드를 브라우저에서 확인한다. 보안은 실패 폐쇄와 안내를 재검토한다.

기획·미디어·디자인은 기존 범위와 계약을 바꿀 근거가 없어 별도 수정 역할을 생략한다. 리더는 결과와 제한을 문서에 반영한다. 이번 분석은 제품 수정이나 위임을 하지 않았다.

## 검증 근거와 제한

독립 QA의 관련 backend 47 passed/1 skipped 및 TypeScript 통과는 fixture 중심이다. Auth의 전체 338 passed/17 skipped는 별도 임시 fixture 실행이며 최종 소규모 변경 전 결과다. DPAPI 왕복은 실제였지만 ACL 설치는 mock했고 실제 ACL 준비는 skip이다. 큐 VM 검사는 합성이고 Playwright 수집은 실행이 아니다. production build·E2E와 Node 일부 검사는 `spawn EPERM`으로 중단되어 제품 결함으로 단정하거나 통과로 보고할 수 없다. 허용된 환경에서 재실행하되 제한 우회는 제안하지 않는다. 실제 ACL·재시작, NASA 인증/파일, LIVE_STAC와 운영 앱 Kakao 반영은 별도 증거가 필요하다.
