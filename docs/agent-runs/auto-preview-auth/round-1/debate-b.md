# 토론인 B — 회차 1 독립 의견

## 강점과 실제 도움

- 화면에 들어온 장면만 자동 확인하고 같은 장면의 요청을 공유하며 동시 실행을 2개로 제한한다. 사용자는 매 장면에서 접근 확인을 누르지 않아도 된다. `providerPreviewQueue.ts`, `ProviderPreview.tsx`의 취소·generation 검사와 세션 단일 준비는 화면 전환과 만료 경합을 줄인다. 원본 다운로드는 명시 버튼에서만 시작하고 만료 영수증 재확인은 한 번으로 제한한다. 자동 이미지는 분석용 원본이 아니라고 표시한다.
- NASA 토큰을 브라우저에 주지 않고 사용자 범위 DPAPI와 제한된 저장소를 사용하며, 갱신 중 로그아웃의 메모리 재생성을 막는다. 공개 callback을 차단하고 제공처별 상태를 구분한다. 이는 저장 평문 노출과 잘못된 연결 기대를 줄이는 설계다.

## 문제와 미충족

- **높음:** `earthdata_store.py` 삭제 실패는 현재 인스턴스만 불가로 만들고, `earthdata_auth.py`는 503에도 쿠키를 지운다. 디스크에 남은 grant는 재시작 후 복사된 이전 SID로 복원될 수 있으며 같은 브라우저의 재시도 성공은 폐기 증거가 아니다. 실제 악용은 검증되지 않았다. 내구성 있는 폐기 기록이나 저장소 전체 격리는 해당 기록을 안전하게 기록·확인할 수 있을 때 재시작 복원을 막을 수 있다. **모든 지속 저장 쓰기가 실패하고 제공처 폐기도 불가능한 조건에서는 소프트웨어가 영구 폐기를 보장할 수 없다.** 이 경우 성공을 주장하지 말고 운영자 복구·제공처 철회와 확인 가능한 격리를 안내해야 한다.
- `EarthdataConnection.tsx`는 로그아웃 503을 일반 오류로 처리해 디스크 폐기 실패의 의미와 기존 연결 표시의 불확실성을 충분히 전달하지 못한다. 다른 탭과 미리보기의 상태도 즉시 무효화·재조회할 필요가 있다. 원본/미리보기 저장은 Blob 수신과 재검사 중 장면·인증 변경에 취소 경로가 있지만 실제 브라우저에서 파일 저장과 경합은 미검증이다.
- QA의 관련 backend 47 통과·1 건너뜀은 fixture 결과이고 TypeScript는 통과했다. production build와 E2E는 `spawn EPERM`으로 완료되지 않았으며 테스트 수집은 통과가 아니다. viewport, 중복·동시성, 만료 복구, 다운로드 및 모바일 실제 동작을 확정할 수 없다. 실제 ACL 설치·재시작 복원, NASA 로그인/갱신/파일 접근과 Kakao 실조회도 미검증이다.
- 검색은 기존 3개 제공처·4개 컬렉션에 한정된다. USGS/CDSE 신규 원본 인증 및 전체 위성 연결은 미구현이며 NASA 연결도 실제 계정 권한을 보장하지 않는다. 현재 실행 서버의 Kakao 설정 인식 문제도 실조회로 해결 확인되지 않았다.

## 회차 2 우선순위

1. 폐기 실패 시 재시작 복원 방지의 지속적 실패 폐쇄 설계와 명확한 불가능 조건을 마련하고, 삭제 실패→권한 복구→재시작→이전 SID 및 재시도를 검증한다. 503에서 폐기 미확인 안내, 로컬 상태 무효화와 다른 탭 통지를 함께 수정한다.
2. 허용된 실행 환경에서 production build와 브라우저 E2E를 실제 실행한다. 가시성·중복·동시 2개·인증/장면 변경 지연 응답·반복 만료·원본 자동 요청 0 및 명시 다운로드를 검증하고 실패를 그대로 기록한다. 실제 Windows ACL/재시작과 계정 준비 후 제공처 접근도 별도로 검증한다.

후속 개선: DNS 검증과 연결 사이 재해석 위험은 보안 보고의 미재현 가설로 남겨 연결 시 주소 검증을 검토한다. 실사용 계정과 파일 매핑이 준비되면 USGS/CDSE를 제공처별로 검증한다. 본 의견은 독립 초기 검토이며 상호 토론은 아직 진행되지 않았다. 제품·테스트 수정이나 테스트 실행은 하지 않았다.

## A 의견에 대한 수용·반론

A의 폐기 실패와 로그아웃 503 지적을 수용한다. 독립적이고 확인 가능한 지속 폐기 기록이나 키 무효화가 실제로 성공해야 재시작 후 복원 차단을 보장할 수 있다. 모든 지속 쓰기와 제공처 철회가 실패하면 기존 grant의 영구 폐기는 보장할 수 없고, 로컬 폐기와 NASA 측 토큰 철회도 별개다. 그 조건을 해소할 신뢰 가능한 수단이 검증되기 전에는 Windows 영속 복원을 기본 비활성화하고 명시적 선택과 한계를 안내하는 A의 보수적 제안에 동의한다. 다만 기본 비활성화만으로 이미 디스크에 남은 grant가 삭제되거나 다른 설정에서 복원되지 않는다고 단정할 수 없으므로 기존 저장 데이터의 처리와 복원 차단도 검증해야 한다.

503에서는 폐기 미확인을 구체적으로 표시하고 현재 탭·다른 탭의 인증 및 큐 상태를 무효화하고 재조회해야 한다. 쿠키 삭제 후 재시도 성공을 기존 grant 폐기의 증거로 삼지 않는다. A와 같이 build와 브라우저 E2E의 `spawn EPERM`은 미검증으로 남기고, 실제 ACL·재시작 복원과 제공처 로그인도 별도 실검증 전 성공으로 보고하지 않는다. 이는 A 의견에 대한 한 차례 응답이며 새 구현이나 검증을 수행한 것은 아니다.
