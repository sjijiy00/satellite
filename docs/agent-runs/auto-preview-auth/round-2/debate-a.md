# Debater A — 회차 2 독립 최종 의견

## 판단과 장점

자동 미리보기와 선택형 NASA 연결 유지는 구현됐지만 사용자 요구 전체의 완료를 확정할 수 없다. `ProviderPreview.tsx`의 가시성 관찰과 `providerPreviewQueue.ts`의 공유 큐·동시 2개·preview-only 요청, 명시 원본 다운로드는 요구에 맞는 설계다. 실제 자동 렌더와 브라우저 요청 수는 아직 확인되지 않았다.

회차 1의 높은 폐기 위험은 **조건부로 해소**됐다. `earthdata_store.py:346-351,386-401`에서 폐기 journal을 확인한 뒤 DB를 삭제하고 복원 시 기록을 검사한다. journal 저장 성공과 DB 삭제 실패를 주입한 fixture는 별도 프로세스에서 이전 SID의 복원을 거부했다. 기본은 메모리이며 `EARTHDATA_PERSIST_SESSIONS=1`에서만 영속 저장·복원을 선택한다. 구형 저장소는 자동 복원하지 않는다.

`earthdata_auth.py:458-492`의 503은 cookie를 보존해 같은 SID로 재시도하게 한다. `EarthdataConnection.tsx:77-132`는 실패를 미확인으로 유지하며 표시·요청·큐를 무효화한다. 최종 보안 보고가 다른 탭의 성공 신호 처리 지적을 철회한 것을 확인했다. 다만 탭 간 통지는 localStorage 가용성에 의존하고 실제 브라우저에서 검증되지 않았다.

## 남은 한계와 개선

- 모든 지속 쓰기가 실패하면 현재 프로세스의 차단만 가능하며 재시작 후 복원 방지나 영구 폐기를 보장하지 못한다. 권한 복구 후 원래 cookie로 명시 재시도하고, 필요하면 저장소 전체를 확인 가능하게 격리하고 NASA 측 철회를 따로 확인해야 한다. 로컬 폐기는 제공처 철회가 아니다. 실제 ACL 및 비정상 종료 내구성은 미검증이다.
- USGS/CDSE 신규 원본 인증은 미구현이고 NASA 실제 로그인·refresh·인증 원본도 미검증이다. 기존 3개 제공처·4개 컬렉션 검색을 전체 제공처 인증 완료로 표현할 수 없다.
- 리더의 실제 검증용 앱에서 Kakao `/places/search`는 HTTP 200, resolved 1건, camera-only였다. NASA 공개 browse는 원본 assets 0인 preview-only 검사 후 이미지 HTTP 200과 70,963바이트를 수신했다. 이는 실제 API 증거이나 브라우저 자동 표시, 지도 이동, NASA 로그인이나 원본 다운로드의 증거는 아니다. 기존 3000/8000에는 새 설정 반영이 확인되지 않았다(`leader-live-checks.md`).
- QA 독립 최종 핵심 검사는 68 passed/1 skipped, TypeScript 통과다. OAuth grant는 fixture이며 실제 DPAPI를 사용한 저장 테스트에서도 ACL 설치는 mock했다. 전체 359 passed/17 skipped는 마지막 응답 메타데이터 변경 **전** 담당자 결과다. 프런트 VM 검사는 fixture이고 Playwright 31개 수집은 실행이 아니다. build/E2E는 `spawn EPERM`으로 완료되지 않아 허용된 환경에서 실제 브라우저·build·ACL 및 인증 확인이 남는다.

추가 구현 사이클은 제안하지 않는다. 본 의견은 B의 회차 2 의견을 보지 않은 독립 초기 검토이며 직접 테스트나 제품 수정을 하지 않았다.

## B 의견에 대한 응답

B의 부분 충족 판정과 조건부 폐기 보장, 기본 메모리 모드 및 검증 한계를 수용하며 실질적 이견은 없다. 유효한 journal이 보존·검사될 때만 재시작 복원 차단을 주장할 수 있고, 모든 지속 쓰기 실패 시 영구 폐기는 보장되지 않는다. 남은 개선은 허용된 환경의 build·브라우저 E2E·실제 ACL/재시작 및 전원 손실·저장소 롤백 내구성 검증, 운영 서버 반영과 지도 확인, 실제 NASA 인증 및 USGS/CDSE 원본 연동 검증이다. 공개 browse와 Kakao 실조회는 해당 추가 검증의 대체 근거가 아니다.
