# 연구 작업 흐름 — 2026-11-04

이번 계약은 이전의 **지명에서 AOI 자동 생성**, **공통 결과 15분/재시작 소실** 계약을 대체한다. 기존 Next.js·MapLibre·FastAPI·단일 Workspace·제품 계산식·QA 정책·인증 정책을 유지했다. 최신 실행 결과는 [TEST_REPORT](../TEST_REPORT.md)를 따른다.

## 연구자가 확인할 순서

1. `/`에서 목적·기간을 입력하거나 직접 선택한다. 자동 AI 전송·비용 고지는 유지하며 이번 개발 검증의 AI 응답은 mock이다. 날짜 폼·촬영일 그룹은 UTC 기준이다.
2. 지명 원문으로 서버 Kakao 조회 → 상위 지역·공식 응답 명칭·경도/위도 후보 선택 → 카메라 이동. `수원`은 `경기 수원시` 후보와 일치하지만 중심점은 수원시 경계가 아니다.
3. 지도 두 꼭짓점 또는 좌표를 직접 지정·확정한다. 지명 선택은 기존 AOI를 변경/삭제하지 않는다. 새 위치에서 다시 지정하려면 명시 링크를 누른다. 검색 bbox 통계를 행정경계 통계로 부르지 않는다.
4. 기존 제품 추천·명시 검색 → UTC 날짜/장면·밴드 선택 → `세부 분석 선택으로`. 원본만 내려받고 종료해도 된다.
5. `/processing`에서 세부 분석·제품/필수 QA·기준/비교 영역 확인 → 계획 검사 → 규모/상한·산출물 확인 → 실행 → 실제 결과 검토 → ZIP 전체 저장·GIS 재열기.
6. `내 결과 보관함 · 재시작 후 찾기`는 같은 브라우저의 과거 파일만 조회한다. 이전 결과를 현재 지도에 적용하거나 다시 실행하지 않는다.

추천 적합 / 검색 가능 / 원본 접근 / 실제 AOI QA / 분석 성공 / 파일 전달은 각각 별도 상태다. 서버는 canonical Item Asset을 다시 조회·범위 읽기한다. 브라우저에 받은 TIFF는 서버 입력이 아니며 로컬 업로드는 미지원이다. 전문가 밴드 변경은 유지하며 서버 카탈로그의 필수 밴드를 명시적으로 복원할 수 있다.

## 장소와 실제 검증

- 기존 실행 서버는 설정 `ready=true`였지만 `수원`은 HTTP200/0건이었다. 새 코드의 공식 주소 `similar` 조회와 행정 구성요소 비교에서는 실제 REGION `경기 수원시`, 중심 `[127.028715898311,37.2635846787741]`을 확인했다. AI 추출 성공과 위치 조회 성공은 별개다.
- 원인 분리용 실제 `exact` 요청도 같은 REGION을 반환했다. 그 응답은 기존 문자열 필터에서 거절되고 수정 필터에서 허용됐다(`kakao-exact-filter-diagnosis.json`). 따라서 이번 수원 0건의 확인된 원인은 키/서버 장애가 아니라 `수원`/`수원시` 후보 필터이며, exact API 자체가 0건이었다고 단정하지 않는다. 반영 후 현재 사이트의 실제 모바일 브라우저에서도 후보 선택/카메라 이동/AOI 불변을 확인했다.
- 주소 API의 `REGION`만 행정 후보로 허용한다. 행정 접미사와 공백을 정규화하되 요청한 모든 구성요소가 계층 순서대로 있어야 한다. `서울 강서구`에 부산 강서구를, `수원 영통구 매탄동`에 수원시만 반환하는 것을 일치로 인정하지 않는다. 추측한 좌표·상위 지역 대체는 없다. 모든 후보는 사용자가 선택한다.
- 0건/미설정/401·403 인증 실패/429 제한/timeout/스키마 오류를 분리한다. 실패해도 직접 지도·좌표 입력으로 계속할 수 있다. IME·debounce·최신 세대 ID·수동값 보호·취소를 유지한다.
- REST 키는 고정 HTTPS 목적지의 서버 Authorization 헤더에만 사용한다. 전체 문장을 Kakao에 보내지 않는다. 분당10회·프로세스100회·동시1·8초·1페이지30결과 상한, 화면의 직전 조회60초 재사용을 유지한다. 제공처 결과를 서버 지명 DB로 축적하지 않는다. 화면에 출처를 표시하며 영구 오프라인 지명 데이터셋/재배포 권한을 추가하지 않는다.
- 공식 근거(확인 2026-11-04): [주소 API](https://developers.kakao.com/docs/ko/local/dev-guide), [운영정책](https://developers.kakao.com/terms/ko/site-policies). 서비스 앱의 권한·쿼터·표시/이용 조건은 운영자가 계속 준수해야 한다. 새 계정/키/과금은 설정하지 않았다.

## 제한된 큰 AOI 실행

서버 `analysis_catalog.py`가 한도의 단일 원천이다. 기존 단일 시점 NDVI/MNDWI/NDBI·PC Landsat L2SP 온도/고온/두 영역 비교에만 최대 **200km²·600,000셀·36타일**을 선언한다. 같은 제공처/제품 allowlist와 기존 제품별20/30m 격자를 유지한다. 50km² 또는150,000셀을 넘으면 고정 격자의160×160 core·1셀 read halo로 읽는다. core는 겹치지 않으며 원본 범위 밖 타일은 미관측으로 기록한다. 실패 타일이 있으면 전체 실패·산출물 없음이며 부분 결과를 성공으로 게시하지 않는다.

각 타일은 기존 원본 window100만셀·입력64MiB·최대128 요청(단기 SAS 포함)·60초를 넘지 않는다. 전체는 입력256MiB·최대512 요청·범위 읽기240초/자식 프로세스255초·ZIP16MiB·보관소 용량을 검사한다. 면적 가중치는 기존 부분 셀 교차 알고리즘을 작은 블록에서 계산한다. 실제 타일 수·전체 격자·예산은 실행 전 계획에 표시한다. 원본의 단일 읽기/요청/캐시 상한·HTTPS/허용 호스트/리다이렉트 거절·ETag·QA/보정은 유지한다.

**확대하지 않은 엔진:** S2 QA·NDVI 변화와 광학 MNDWI 변화50km²/150,000셀, 기존 관측 합성/제한 ML25km²와 시점/기간/검증 게이트. HLS·VIIRS·SAR·PC S2의 픽셀 분석, 침수 확정·토지피복 확정 분류, 임의 도시 전체 분산 처리는 미지원이다. 한도 초과 시 사용자 AOI를 그대로 거절하며 직접 축소할 것을 안내한다.

실제 검증은 S2B 한 장면의79.594684km²/450×444/9타일이다. 고정 실제 TIFF fixture에서는 S2 NDVI와 Landsat ST의 단일 읽기/타일 core 배열·마스크·면적 일치를 비교했고 구름/NoData·부분 실패·미관측을 검사했다. **모든 제품의 대형 실연결이나 200km² 상한 근처 성능을 검증한 것은 아니다.** 서울 포함 약1,100km² bbox는 여전히 차단한다.

## 로컬 결과 보관과 소유권

- 기본 경로 `backend/.private/processing/`: 실제 파일/ZIP과 SQLite 작업 journal. `backend/.private/work-session.key`는 로컬 무작위 서명 키다. 환경파일·제공처 토큰이 아니며 브라우저에 보내지 않는다. `.private`는 기존 Git 제외 대상이고 웹 정적 경로로 제공하지 않는다. 운영체제의 사용자 전용 폴더 권한으로 보호해야 한다.
- 기본 파일7일·1GiB, 사용자 최대20개/전체100개 작업·행별 메타데이터2MB. 계획은 기존15분/8개다. 파일 정리는 요청 시 만료된 전용 작업 디렉터리에만 적용한다. 다른 사용자 파일을 삭제하지 않는다. 만료 journal은 추가1일 안에서 정리한다. 임의 자동 용량 퇴출은 없고 한도/여유 공간 부족이면 새 출력을 거절한다.
- 설정은 시작 프로세스 환경변수 `PROCESSING_RETENTION_SECONDS`(60~2,592,000), `PROCESSING_STORAGE_MIB`(64~8192), `PROCESSING_WORKERS=1`로 받는다. 현재 `backend/.env` allowlist에 자동 추가하지 않았으므로 PowerShell에서 `$env:...`를 정한 뒤 `./start.cmd`로 실행한다. 이번에는 설정값을 바꾸지 않았다.
- 소유권은 HttpOnly/SameSite=Strict·HTTPS 시 Secure·최대7일 쿠키다. 같은 서명 키를 재시작 후 재사용한다. 쿠키와 서명 URL은 브라우저 영구 저장소·manifest·journal에 저장하지 않는다. journal은 비밀 없는 입력/결과를 HMAC 서명하고 다운로드/보관 조회에서 ZIP 전체 SHA-256을 확인한다. 변경·누락·만료를 구분한다.
- 재시작 전 성공 작업은 복원하되 queued/running 작업은 실패·재실행 필요로 전환한다. 자동 재실행은 없다. 중복키·다른 세션404·취소·만료·디스크 상한을 유지한다. 다른 프로세스의 같은 보관소 실행은 파일 lease로 차단한다. 다중 worker/다중 서버/공개 계정 서비스는 지원하지 않는다. 기존 전송 쿼터는 프로세스 단위이며 재시작 간 사용량 집계 영속화는 별도 과제다.
- 최초 도입 전 메모리 작업·옛 쿠키는 새 소유권으로 이관할 수 없다. 쿠키·서명 키·실제 파일 중 하나라도 소실되면 임의 소유권 복원은 제공하지 않는다. 7일을 넘는 파일 보관을 설정해도 쿠키 수명은7일이므로 그 전에 GIS 파일을 저장한다. 연구용 영구 보관은 사용자가 받은 ZIP/TIFF와 manifest로 한다.

> 영속 보관은 새 공통 `/processing/jobs` 경로에 한정한다. 기존 `/cloud/jobs`·`/estimate/jobs` 및 직접 반환하는 구형 A4 결과는 기존 메모리/임시 보관을 유지하므로 즉시 다운로드해야 한다. 같은 QA/NDVI 변화/관측 합성/제한 ML도 공통 처리 방법에서 실행한 작업만 새 보관함·재시작 복원 대상이다.
