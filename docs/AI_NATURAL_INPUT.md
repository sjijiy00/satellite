# 자연어 해석·지도 이동·분석 AOI

> 현재 계약(2026-11-02): 아래의 과거 규칙/AI 버튼/수동 영역 적용 흐름은 [AI 중심 조건 입력](AI_PRIMARY_INPUT.md)으로 대체했습니다. 기본·실패 경로에서 규칙 추출을 사용하지 않으며 명확한 AI+실제 위치/경계 결과를 자동 AOI에 반영합니다. 아래는 이전 구현의 출처·설정·설계 이력입니다.

> 최신 2026-11-02 지명 공통 조회·서울 경계 제안/AOI 외접 범위 적용은 [ADMINISTRATIVE_AOI.md](ADMINISTRATIVE_AOI.md)를 우선한다. 아래 초기 카메라 전용/AI 위치 조회 설명은 당시 범위다. 점 좌표는 계속 카메라 전용이며 AI 자동 실행 정책은 바꾸지 않는다.

2026-10-30 최신 동작이다. 국내 지명 검색·단일 폼 목적 연결의 최신 상세 계약은 [AI_PLACE_CONDITIONS.md](AI_PLACE_CONDITIONS.md)를 따른다. 기존 자동입력 문서의 지명→AOI 자동 반영 동작은 이 문서로 변경된다. 추천 카탈로그·STAC 검색·A3/A4·관측 합성·ML 픽셀 추정 엔진은 유지한다. 여기서 OpenAI 자연어 해석과 기존 ML 픽셀 추정은 서로 다른 기능이다.

## 사용자 순서

1. `영천군의 2025년 8월 식생상태를 확인하고 싶어`를 입력한다. 일시 정지(800 ms)/blur는 무료 규칙 해석이다. 날짜는 UTC 달력의 2025-08-01~31로 제안·반영하고 지도 화면만 해당 지명으로 이동한다.
2. 지명은 카메라의 화면 맞춤에만 사용한다. 사각 AOI/좌표를 만들지 않는다. 등록된 자료가 없거나 지명이 모호하면 안내/후보 선택을 제공한다. 영천군은 1995년 통합된 옛 지명으로 표시하며 현재 영천시의 공개 극점을 화면 참고로 사용한다. 옛 군 경계나 현재 법정경계 폴리곤의 복원이 아니다.
3. 사용자가 지도에서 두 꼭짓점을 선택한 다음 `분석 AOI 확정`, 또는 좌표를 입력한 다음 `좌표 적용`을 누른다. 좌표를 고치면 다시 확정해야 한다. 확정 전에는 실제 검색/픽셀 작업에 진입하지 않는다. 이미 수동 AOI가 있는 상태에서 새 지명을 해석하면 좌표를 보존하고 `기존 AOI 유지`/`새 영역 선택`을 확인한다. 새 영역 선택도 기존 좌표를 즉시 삭제하지 않는다.
4. 기존 추천 제품 → 명시적 검색 → 장면 선택 → 목적에 맞는 다음 작업을 사용한다. 카메라 이동/수동 지도 탐색만으로 기존 검색 조건·결과를 폐기하지 않는다.
5. OpenAI가 서버에 설정되면 `AI로 문장 해석`을 명시적으로 누를 수 있다. 버튼을 누를 때만 문장이 제공처에 전송된다. 새 입력·IME·취소는 오래된 응답을 무효화한다. 수동 날짜/목적/관측 시점/AOI는 우선 보호한다. 충돌을 확인한 사용자의 `문장에서 다시 적용`은 제안된 목적·날짜·분석 형태를 명시 재적용하며 AOI를 만들지 않는다. 지명 추출/실제 위치 검색/지도 이동/AOI 확정은 별도 단계다. Kakao 키 미설정은 지역 언급 없음이 아니라 위치 검색 미설정으로 표시한다.

## OpenAI 서버 설정 — 2026-10-30

로컬 런처는 **프로젝트 루트 기준 `backend/.env` 하나만** 읽는다. 루트/프런트 `.env`나 `.env.example`을 추측해서 합치지 않는다. 일반 실행은 루트 `start.cmd` 그대로다. uvicorn을 단독 실행하면 Node 로더를 거치지 않으므로 프로세스 환경을 별도로 준비해야 한다.

키가 든 기존 파일이 `backend/.env.example`인 경우, 기존 자격증명의 지속 사용에 대한 사용자 승인 뒤 `node scripts/configure-server-env.mjs --apply-approved`를 사용한다. 파일 자체를 `backend/.env`로 이름 변경하고 안전한 예시를 새로 만든다. 키 값의 출력/별도 파일 복사 없이 원래 파일과 다른 설정을 보존한다. 실제 설정 파일이 이미 있는데 키 든 예시도 있으면 자동 처리하지 않는다. 이 명령은 승인 대신 사용할 수 없으며 사전 승인 없이 실행하지 않는다.

기존 `OPENAI_API_KEY` 행은 보존하고 일반 설정은 다음과 같다. 사용자가 이미 지정한 모델이 있으면 덮어쓰지 않는다.

```dotenv
AI_NL_ENABLED=1
AI_NL_PROVIDER=openai
AI_NL_MODEL=gpt-5.6-luna
```

선정 모델은 [GPT-5.6 Luna 공식 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)에 따라 비용 지향 소형 추출 작업에 맞췄다. Responses와 Structured Outputs, reasoning `none`을 지원한다. 2026-10-30 확인 가격은 100만 토큰당 입력 $0.20 / 출력 $1.20이며 실제 계정 접근·응답 성공은 별도 검증이다. 이 모델을 선택한 경우 기존 호출 경로에서 `reasoning.effort=none`을 설정해 추론 토큰/지연을 줄인다. 다른 사용자 모델의 요청 설정은 바꾸지 않는다. 계정 모델 조회와 실제 유료 호출은 이번 설정 단계에서 하지 않는다.

| 변수 | 의미 |
|---|---|
| `AI_NL_ENABLED`, `AI_NL_PROVIDER`, `AI_NL_MODEL` | 위 일반 설정. 모델 접근 가능 여부를 로컬 설정만으로 보장하지 않음 |
| `OPENAI_API_KEY` | 서버 전용. 기존 값을 보존하며 채팅·로그·예시·프런트·NEXT_PUBLIC로 전달하지 않음 |
| `AI_NL_INPUT_USD_PER_MILLION`, `AI_NL_OUTPUT_USD_PER_MILLION` | 선택 단가. 사용자가 입력한 값은 보존. 미설정 비용은 미확인으로 표시 |

우선순위는 **이미 존재하는 프로세스 환경변수 > `backend/.env`의 허용 목록 > 기존 앱 기본 동작**이다. 프로세스 값이 빈 문자열이어도 파일로 대체하지 않는다. 파일의 다른 변수는 파일 안에 보존하되 백엔드 환경에 임의 주입하지 않는다. 변수 치환/셸/스크립트는 실행하지 않는다.

런처는 백엔드에만 OpenAI 설정을 주고 Next.js 및 지도 worker 준비 프로세스에는 `OPENAI_*`, `AI_NL_*`, `NEXT_PUBLIC_OPENAI_*`, `NEXT_PUBLIC_AI_NL_*`를 제거한 별도 환경을 준다. 독립 검증도 루트에서 `node scripts/frontend-check.mjs typecheck` / `node scripts/frontend-check.mjs build`를 사용하면 정제된 환경으로 실행한다. 이 프런트 검증 명령은 서버 `.env` 자체를 읽지 않는다.

`.gitignore`에서 `.env*` 및 명시 `/backend/.env`를 제외한다. `.env.example`은 공유 가능한 예외이므로 실제 키를 두지 않는다. 현재 폴더가 Git 저장소가 아니라면 추적/과거 이력의 부재를 별도로 명시하며 ignore 설정만으로 과거 노출이 제거됐다고 표현하지 않는다.

`GET /request/config`와 `/api/request/config`는 키 값을 반환하지 않고 `ready`, `provider`, `model`, `missing_settings`(변수 이름만)와 집계를 제공한다. **ready=true는 설정 인식 성공**이며 실제 모델 접근/응답 성공이 아니다. 설정 적용 후 재시작 전에 현재 프로젝트의 AI 실행 상태와 래스터 처리 프로세스를 확인한다. 기존 서버에는 전체 메모리 작업 목록 API가 없어 대기 작업 전부를 확인했다고 단정하지 않는다. 다른 앱/서버는 중지하지 않는다.

실제 모델 검증은 별도 승인을 받은 다음에만 한다. 제안하는 최소 검증은 선택된 모델에 `영천군의 2025년 8월 식생상태 확인` 한 문장으로 기존 strict schema 요청 **1회**, 1000 출력 토큰/12초/도구 없음/`store:false` 조건에서 목적·기간·지명 필드를 확인하는 것이다. 영상 검색/픽셀 처리·키 재발급은 하지 않는다. 실패 시 자동 유료 재시도를 하지 않는다.

## 요청·비용·출력 제한

- AI는 명시 버튼에서만 호출한다. 자동 규칙 해석과 선택 영상 이후 기존 후속 의도 해석은 OpenAI를 호출하지 않는다.
- 원문 최대 2000자, 출력 최대 1000토큰, 제공처 전체 대기 12초, 브라우저 AI 대기 15초(규칙 10초), 응답 최대 64 KiB. 자동 재시도 없음. 모델에 따라 reasoning 토큰 때문에 불완전 응답이 오면 성공으로 사용하지 않는다.
- 서버 프로세스 내 동시 1개, 분당 6회, 프로세스당 총 100회. 실패·취소 요청도 호출 상한에 포함한다. 동일 모델+문장의 성공 추출은 해시 키의 10분 RAM 캐시(128건), 브라우저는 문장/모드/선택 후보의 10분 캐시(16건)로 중복을 막는다. 후보 선택은 기존 추출 캐시를 재사용할 수 있다.
- 재시작하면 캐시·사용량·상한이 초기화된다. 다중 서버/사용자별 청구·영속 과금 원장이 아니다. 서버/브라우저 취소는 제공처의 이미 발생한 비용 환불을 뜻하지 않는다. API 대시보드에서 실제 청구를 확인한다.
- UI는 호출·실패·서버 캐시·보고된 입력/출력 토큰·선택 단가 기준 추정 USD 또는 미확인을 표시한다. `AI 사용량 새로고침`은 집계 조회만 하며 추가 AI 추론을 호출하지 않는다. 취소/네트워크 오류의 토큰 미확인 호출도 구분한다.
- OpenAI Responses를 고정된 공식 HTTPS 원점에 요청하며 `store:false`, strict JSON schema를 사용한다. 도구 호출·셸·웹 실행·대화 연결은 사용하지 않는다. 키는 Authorization 헤더에만 쓰고 응답 원문·원문 문장·키를 로그/디스크에 기록하지 않는다. OpenAI의 보존 정책 전체가 `store:false` 하나로 결정되는 것은 아니다.

## 서버 검증과 API 계약

`POST /request/interpret`의 기존 문맥 필드는 유지하고 `interpretation_mode: rules | ai`(기본 rules)를 추가했다. `resolve_conditions=true`일 때만 조건 제안과 선택형 AI를 사용한다. 조건 제안의 `engine`은 rules/ai와 succeeded/cached/not_configured/timeout/invalid_response/provider_error/limited/busy 등을 구분한다. 오류 시 날짜·지명 제안을 absent로 반환하고 기존 수동 상태를 보존한다. 실패한 AI 요청을 성공한 규칙 해석으로 위장하지 않는다.

AI schema는 목적(enum/nullable), 원문 근거, 명시 날짜 원자(year/month/day/근거), 지명 문자열/모호성, single/change/unspecified, 불확실성만 허용한다. 좌표·위성 사양·가용 영상·품질·실행 명령 필드는 금지한다. 원문 근거와 지명 부분문자열, 날짜 달력/윤년/월말/366일 상한, 상대 날짜/검색 범위 모호성, 허용 목적/의도를 서버에서 다시 검사한다. `최근`/`지난달`은 확정하지 않는다. 월 검색 기간에서 사건 기준일을 만들지 않는다. AI 해석 의미의 정확성을 스키마만으로 보장하지 않으며 제안과 불확실성을 사용자에게 표시한다.

지명 결과는 `region.role=camera_only`, `view_bbox`이며 `bbox`가 아니다. AOI는 사용자의 단일 폼 상태에서만 나온다. `CameraLocation`은 별도 상태이고 지도 pan/zoom은 폼에 쓰지 않는다. 카메라 응답 대기 중 사용자가 지도 이동/수동 AOI 작업을 했다면 자동 카메라 이동도 생략하고 명시 이동 버튼을 제공한다. 검색 API의 기존 bbox/기간 계약과 모든 픽셀 API는 유지한다. 서버 API를 직접 쓰는 호출자는 명시 bbox를 제출해야 하며 UI의 확정 상태 자체를 서버 인증으로 취급하지 않는다.
